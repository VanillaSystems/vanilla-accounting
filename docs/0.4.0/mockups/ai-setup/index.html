0.4.0 · mockups · AI setup on a fresh install

KI einrichten

How a person gets from a fresh install of the Mac app to «KI bereit»: Claude Code or Codex installed by the person, with the vendor's official installer, signed in with their own subscription, detected by the app on its own. Two alternatives for the first run (A and B), each in every state, and the places where the same help shows up later. The rules behind them, the detection and the open questions are in docs/0.4.0/ai-setup.md.

Every screen is the real app, captured read-only on the demo workspace (start screen, setup conversation, Firma › KI, Buchungen with the KI column) with its own CSS (app.css); the new parts are written by hand in the app's tokens and class names (ai-setup.css, built by tools/build.mjs). Click a screen to open it full size.

Theme

What holds in both designs

  • The app never touches a login. It runs the CLI's own status commands (claude auth status, codex login status) and keeps the answer: signed in or not, the kind of login and, for Claude, the plan name. No token, no keychain read, no file under ~/.claude or ~/.codex.
  • The person installs. «Im Terminal installieren» opens Terminal with the vendor's own command written out; it runs only after Enter. The command and a link to the vendor's guide are on the card, so the same works by copy and paste.
  • No Node, no Homebrew needed. Both vendors' native installers (curl … | bash, curl … | sh) need only what macOS has. Homebrew and npm appear as other ways only when the app finds them on this Mac.
  • The app notices by itself. While a card waits it looks every 2 seconds (and when the window gets focus), in ~/.local/bin, /opt/homebrew/bin, /usr/local/bin and the shell's PATH. No restart.
  • The minimum plan is a fact on every card: Claude Pro for Claude Code, ChatGPT Plus for Codex, each «etwa 20 USD im Monat», with a link to the vendor's plans page (checked 25.10.2026). A plan too small or a limit reached is stated as what the CLI said, nothing more.
  • «Ohne KI weitermachen» is always there. Everything except reading receipts, booking proposals and the KI column works without an AI (MISSION: whatever the AI does, a person can do by hand).

A · «KI einrichten» before the start screen

A dedicated first step of the Mac app, shown once on a fresh install and whenever no AI is set up and the person has not chosen «Ohne KI weitermachen». Two equal cards, Claude Code and Codex, each with its state, its minimum plan, the official command and one button. «Weiter» unlocks when one is ready; the stepper says what comes next (1 KI · 2 Buchhaltung). After it the existing start screen opens, with the AI as one quiet fact under the choices.

A1 · Nothing installed, no Homebrew, no Node. The official installers need neither; the Mac line says so as a fact.

A1b · Homebrew and Node found. The same primary path; «Andere Wege auf diesem Mac» adds brew install --cask … and npm install -g …, with the fact that Homebrew does not update Claude Code by itself.

A2 · Installing. Terminal is open with the command written out and waits for Enter; the card waits and says it looks every 2 seconds.

A3 · Installed, not signed in. Version and place as found; «Im Terminal anmelden» runs claude auth login, which opens claude.ai in the browser.

A4 · Signing in. The browser has the vendor's page; the app asks claude auth status until it says signed in.

A5 · Ready. Signed in with Claude Pro, version, and one short test call that answered. Codex stays offered, never pushed. «Weiter zur Buchhaltung».

A6 · Errors. Claude: signed in with an account whose plan has no Claude Code, stated with the minimum plan. Codex: nothing found after 15 minutes, with where the app looked and three ways on.

A7 · «Ohne KI weitermachen». The real start screen; one line states that no AI is set up and what that means («Neue Buchhaltung» then uses the form). One link, no reminder.

A8 · Start screen after the setup. The AI as a fact: «KI: Claude Code, angemeldet mit Claude Pro».

B · The setup conversation starts with the AI

On a fresh install the app opens straight into «Einrichtung», the setup conversation the owner chose (design B of the move). Its first message is the AI: the same two cards, stacked, as a card in the conversation; the answers below are the buttons. The conversation's steps are drawn by code, so they run before any AI exists; only typing in your own words waits for one. After «bereit» the conversation goes on with the folder (or «Ich habe schon eine Buchhaltung», «Erst die Demo ansehen»), so the start screen is no longer the first screen.

B1 · Nothing installed. «Eins davon reicht.» Answers: Claude Code installieren, Codex installieren, Ohne KI weiter. The text box says typing comes once an AI is ready.

B1b · Homebrew and Node found. The other ways fold out under each card.

B2 · Installing. «Drück dort Enter. Wenn es fertig ist, merke ich es von selbst.»

B3 · Installed, not signed in. «Anmelden» with what it opens, or switch to Codex, or go on without.

B4 · Signing in. The browser has claude.ai; the conversation waits.

B5 · Ready. One green line with the plan and the test call; the text box opens; the next question is the folder.

B6 · Plan too small. Stated as a fact with the minimum plan; the answers lead to the plans page, another account, Codex, or on without AI.

B7 · «Ohne KI weiter». The conversation goes on with buttons and fields only (it is code-driven), instead of switching to the separate form as today.

Later: the same help where the AI is missing

One component, the CLI card, in every place. Its states and words are the same as in the first run, so what a person learned there they see again.

Firma › KI. «KI-Programme auf diesem Mac» replaces the row «Claude-Abo (Claude Code) · bereit»: both cards, the minimum plans in one sentence, then the API keys (which cost per call) and the model per step.

Second program. Both ready: «Die App fragt» Claude Code or Codex (also what «Im Terminal» opens), and whether to ask the other one when the first cannot answer.

KI column without an AI. The column says what it needs and shows both cards; the composer is off with the reason. Everything else on the page works.

Limit reached. What Claude Code said, as a fact; Codex is signed in, so «Mit Codex fragen» is offered.

The error line where error.noClaude shows today (struck through below it): what the step needed and what this Mac has, «KI einrichten» (opens the cards) and «Von Hand erfassen».

Recommendation

B for a fresh install, A's cards as the one component. The owner chose the conversation for the move, and B makes the AI its first message instead of a gate before it, so a new person meets one voice from the first second. It also removes the odd split of today (the conversation with AI, the form without): the conversation is code-driven and runs either way. A stays the shape for every later place (Firma › KI, the KI column, the error line) and for a person who opens existing books: the same card, stacked in B, side by side in A. Details and the open questions are in ai-setup.md.
